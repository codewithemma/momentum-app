# Security policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public GitHub issues. Contact
the project maintainer through a private channel and include the affected
component, reproduction steps, impact, and a safe way to follow up. Remove
credentials, tokens, and personal data from reports.

> Maintainer action: configure a private security contact (for example, a
> GitHub security advisory contact or dedicated security address) and replace
> this placeholder with the exact reporting channel before the open-source
> launch.

Until a private channel is published, do not disclose suspected vulnerabilities
publicly; ask a maintainer for the approved private reporting route.
